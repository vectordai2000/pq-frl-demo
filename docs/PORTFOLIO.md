## 2. Homepage section (heading + body + bullets)

**EN**

### PQ-FRL: privacy-preserving, quality-aware federated RL

A multi-UAV edge-computing system where every UAV is a DDPG agent. The hard part is not the RL —
it is that the uploaded policy update has to be private, and differential privacy destroys the
signal that tells a good update from a noisy one. My approach releases only two objects per client
per round: a clipped, noised actor update and a clipped, noised average reward. The ground station
then aggregates with a softmax over those protected rewards, so clients that are actually learning
well get more weight without revealing anything extra.

- **System model** — OFDMA uplink, local/edge execution with a hard deadline, rotary-wing propulsion energy.
- **Learning** — DDPG over a mixed action space (speed, heading, offload decision, CPU share), with a straight-through estimator for the discrete offload threshold.
- **Privacy** — output perturbation once per round, with an explicit clipping bound and Gaussian calibration.
- **Aggregation** — reward-weighted softmax; one extra scalar per client, no raw observations.
- **Engineering** — 6 algorithms, cached runs, deterministic evaluations, tests and CI; figures and an animated rollout are generated by the repo.

Links: [GitHub](https://github.com/vectordai2000/pq-frl-demo) · [Paper](https://doi.org/10.1109/JIOT.2026.3695149)

**中文**

### PQ-FRL：隐私保护与质量感知的联邦强化学习

面向多无人机边缘计算：每架无人机是一个 DDPG 智能体。难点不在强化学习本身，而在于上传的策略更新
必须满足差分隐私，而 DP 噪声恰好会掩盖“更新是好是坏”的信号。我的做法是每轮只释放两个对象：
裁剪加噪后的 actor 更新，以及裁剪加噪后的平均奖励；地面站按这些受保护奖励做 softmax 加权，
让真正在变好的客户端获得更高权重，同时不额外泄露信息。

- **系统模型**：OFDMA 上行、本地/边缘执行与硬截止时间、旋翼推进能耗。
- **学习**：混合动作空间（速度、航向、卸载决策、CPU 份额）上的 DDPG，离散卸载阈值用直通估计器。
- **隐私**：每轮一次输出扰动，显式裁剪阈值 + 高斯噪声标定。
- **聚合**：基于奖励的 softmax 加权；每客户端仅多一个标量，不上传原始观测。
- **工程**：6 种算法、训练缓存、确定性评估、测试与 CI；图表与飞行动画均由仓库脚本生成。

链接：[GitHub](https://github.com/vectordai2000/pq-frl-demo) · [论文](https://doi.org/10.1109/JIOT.2026.3695149)

## 4. The answer if someone asks about the original code

Keep it short and factual; it is a normal situation and does not need hedging.

> The paper's full simulation code is no longer available. This repository is a reduced-scale
> re-implementation written from the method section, so it is not numerically comparable with the
> paper — it is meant to make the mechanism inspectable and runnable. The README lists the
> parameter deviations, and every number in the repository is generated by the code itself.

中文：

> 论文的全量仿真代码已不再保留。这个仓库是依据论文方法一节的精简重写，因此数值上不与论文可比，
> 目的是让机制可读、可跑。README 列出了参数偏差，仓库里的每个数字都由代码本身生成。

## 5. If you publish only the component library

The `pqfrl-lib` repository is the low-risk variant: it exposes the building blocks and makes no
experimental claims. Use this card instead of the demo one when that is the public artifact.

**EN**

> **pqfrl — building blocks for privacy-preserving federated RL**
> A small, typed Python library extracted from my IEEE IoT-J work: a UAV-MEC simulator, DDPG agents
> with a mixed action space, a Gaussian-mechanism layer for uploaded updates and rewards, and
> FedAvg / quality-aware softmax aggregation, wired together by a round orchestrator.
> `pip install -e .`; tests, linting, type checking and CI included.

**中文**

> **pqfrl —— 隐私保护联邦强化学习的组件库**
> 从本人 IEEE IoT-J 工作中抽出的可复用组件：UAV-MEC 仿真环境、混合动作空间的 DDPG 智能体、
> 面向上传更新与奖励的高斯机制层，以及 FedAvg / 质量感知 softmax 聚合，外加轮次编排器。
> `pip install -e .` 即可使用；含测试、lint、类型检查与 CI。

For the library it is enough to say: *"components + tests + docs, no benchmark claims."* That is the
whole pitch, and it is much harder to attack than a results page.

## 6. Presentation checklist

- [ ] Pin the repository on GitHub; put the project page link in the About section.
- [ ] Use the animated rollout as the hero visual, the convergence figure as the second visual.
- [ ] Quote only demo numbers, always next to the words *demo* or *illustrative* — never as the paper's results.
- [ ] Keep the "what it is / is not" section visible on the project page; it is what makes the artifact credible.
- [ ] Link the DOI next to the repository, not the other way round: paper first, code as the companion artifact.
